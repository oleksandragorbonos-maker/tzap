Основні кейси TC-001–TC-024 дають 24 кейси, тобто ціль виконано без резерву; резерв розширює покриття і додає негативні пари. Автором F-50 ціна в резерві записано КТ, щоб розвантажити СМ: власницею вимоги F-50 лишається СМ. Правило «один кейс — один набір даних» враховано: TC-021 перевіряє лише категорію, TC-024 лише одне додавання. Окремі кейси для бренду, «Eco-Friendly Products» і правил «І» / «АБО» (F-50), а також «Out of stock» (F-80) не планую; їх додаємо лише після виконання основних кейсів, якщо лишиться час. Вимоги F-50 і F-80 вважаються покритими TC-021, резервним кейсом F-50 і TC-024.

Граничні значення з обґрунтуванням: GUI-30 (0 / 1 / 99 / 100), F-140 (49 / 50 / 250 / 251), F-10 пароль (7 / 8). Таблицю класів еквівалентності готує ТА (SCRUM-108). Для F-100 передбачено один кейс без повного набору меж: межі кількості 1–99 перевіряють TC-005–TC-008 (GUI-30). Для F-50 межі ціни покриває резервний кейс.

| D-10 | Посібника користувача не надано. |
| D-20 | README модуля бізнес-логіки надається у спринті 4. |
