## 1. Продукт і межі тестування

«ШопЛайн» — спеціалізований вебзастосунок електронної комерції (каталог ~600 позицій, 20 брендів, 1 склад у м. Житомир).
- **Архітектура:** Вебзастосунок Angular SPA (фронтенд) + Laravel REST API (PHP, бекенд) + реляційна база даних MySQL.
- **Середовище demo:** Toolshop (`https://practicesoftwaretesting.com`).
- **Модуль бізнес-логіки лояльності:** Окрема Java-бібліотека (JDK 17, без зовнішніх залежностей, пакет `ua.kpi.tzyapz.shopline`, класи `Cart`, `DiscountCalculator`, `PromoCodeValidator`).
- **Межі (In Scope) версії 1.0:** Публічний каталог, пошук, фільтрація, сортування, сторінка товару, кошик, 4-крокове оформлення замовлення, реєстрація/вхід покупця, особистий кабінет, контактна форма, модуль розрахунку знижок і промокодів. Програма лояльності — нова функція; оскільки бібліотека логіки у версії 1.0 ще не інтегрована у вебінтерфейс, тест-кейси через UI на неї не пишуться, а її функціонал перевіряється ізольовано юніт-тестами Java-модуля.
- **Поза межами (Out of Scope) версії 1.0:** Адміністративна панель (керування замовленнями, товарами, користувачами — запланована на версію 1.1), реальний платіжний шлюз (на demo емулюється), мобільний застосунок.

## 2–4. Рівні та типи тестування

### 2.1. Обґрунтування шкали пріоритетів
- **High:** Критичний функціонал ядра системи (каталог, кошик, чекаут, прямі контракти інтерфейсів API, модульні перевірки логіки лояльності та безпека сесій), без яких функціонування неможливе.
- **Medium:** Допоміжні користувацькі сценарії, розширені конфігурації екранів, надійність сесій, відновлення даних, юзабіліті, цільове навантаження за P-20 та перевірка багатопотокових гонок.
- **Low:** Дослідницькі, документаційні, другорядні або обмежені тестовим середовищем задачі (дослідницька перевірка витоків пам'яті SPA-клієнта, перевірка технічної документації, i18n за відсутності локалізованого demo та зовнішнє бета-тестування).

## 6. Припущення й ризики

### Припущення
1. Demo-застосунок Toolshop адекватно моделює поведінку та інтерфейс цільового продукту «ШопЛайн».
2. Числові значення та порогові показники (час сценарію у U-10, поріг безкоштовної доставки 1500 грн, навантаження P-20, допустимий приріст пам'яті 20%) очікують офіційного підтвердження замовником.
3. Окремий локальний серверний тестовий стенд для розгортання повного бекенду «ШопЛайн» поза публічним demo відсутній.

### Ризики
1. **Обмеження публічного демо-сервера:** На публічному ресурсі `practicesoftwaretesting.com` заборонено проводити навантажувальні тести (`P-20`) та агресивні сканування захищеності через ризик блокування стенда.
   - *Наслідок:* неможливість виконання навантажувальних і активних перевірок безпеки на реальному стенді.
   - *Пом'якшення:* сценарій навантажувального тестування детально описано, виконання перенесено на локальний стенд після його розгортання; питання буде винесено на демо замовнику.
   - *Власник:* ІТ (Дрєпіна Анастасія).
2. **Розбіжність демо і продукту (обсяг каталогу):** Публічне demo містить лише 52 товари на 6 сторінках замість ~600 позицій та 20 брендів за профілем продукту.
   - *Наслідок:* неповне покриття перевірок каталогу на великих обсягах даних (тип 9) у середовищі demo.
   - *Пом'якшення:* розрахунки кошика перевіряються на штучних вибірках у модульних тестах; повний обсяг каталогу (~600 позицій) — на тестовій базі замовника.
   - *Власник:* ІТ (Дрєпіна Анастасія).
3. **Нестабільність та періодичне скидання бази demo:** Дані demo-застосунку періодично скидаються адміністраторами платформи.
   - *Наслідок:* втрата тестових даних та створення залежностей між сеансами.
   - *Пом'якшення:* розробка автономних тест-кейсів, не залежних від попередніх замовлень чи створених користувачів.
   - *Власник:* ІТ (Дрєпіна Анастасія).

   - *Наслідок:* відсутність збору реальних метрик від бізнес-користувачів до релізу.
