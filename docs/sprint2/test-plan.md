## 1. Продукт і межі тестування

«ШопЛайн» — спеціалізований вебзастосунок електронної комерції (каталог ~600 позицій, 20 брендів, 1 склад у м. Житомир).
- **Архітектура:** Вебзастосунок Angular SPA (фронтенд) + Laravel REST API (PHP, бекенд) + реляційна база даних MySQL.
- **Середовище demo:** Toolshop (`https://practicesoftwaretesting.com`).
- **Модуль бізнес-логіки лояльності:** Окрема Java-бібліотека (JDK 17, без зовнішніх залежностей, пакет `ua.kpi.tzyapz.shopline`, класи `Cart`, `DiscountCalculator`, `PromoCodeValidator`).
- **Межі (In Scope) версії 1.0:** Публічний каталог, пошук, фільтрація, сортування, сторінка товару, кошик, 4-крокове оформлення замовлення, реєстрація/вхід покупця, особистий кабінет, контактна форма, модуль розрахунку знижок і промокодів. Програма лояльності — нова функція, тест-кейси через графічний інтерфейс на неї у версії 1.0 не пишуться; вона ізольовано перевіряється юніт-тестами Java-модуля.
- **Поза межами (Out of Scope) версії 1.0:** Адміністративна панель (керування замовленнями, товарами, користувачами — запланована на версію 1.1), реальний платіжний шлюз (на demo емулюється), мобільний застосунок.

## 6. Ризики й припущення

1. **Обмеження публічного демо-сервера:** На публічному ресурсі `practicesoftwaretesting.com` суворо заборонено проводити навантажувальні тести та спроби порушення захищеності. Оскільки локального стенда для «ШопЛайн» немає, такі тести на demo не виконуються.
2. **Періодичне скидання бази demo:** Дані demo-застосунку періодично скидаються, тому тести мають бути незалежними від попередніх замовлень чи створених користувачів.
3. **Модуль лояльності поза UI:** Оскільки бізнес-логіка програми лояльності у версії 1.0 реалізована окремою бібліотекою і ще не підключена до вебінтерфейсу, перевірка правил нарахування та розрахунку проводиться на рівні Unit-тестів.
