## 1. Продукт і межі тестування

«ШопЛайн» — спеціалізований вебзастосунок електронної комерції (каталог ~600 позицій, 20 брендів, 1 склад у м. Житомир).
- **Архітектура:** Вебзастосунок Angular SPA (фронтенд) + Laravel REST API (PHP, бекенд) + реляційна база даних MySQL.
- **Середовище demo:** Toolshop (`https://practicesoftwaretesting.com`).
- **Модуль бізнес-логіки лояльності:** Окрема Java-бібліотека (JDK 17, без зовнішніх залежностей, пакет `ua.kpi.tzyapz.shopline`, класи `Cart`, `DiscountCalculator`, `PromoCodeValidator`).
- **Межі (In Scope) версії 1.0:** Публічний каталог, пошук, фільтрація, сортування, сторінка товару, кошик, 4-крокове оформлення замовлення, реєстрація/вхід покупця, особистий кабінет, контактна форма, модуль розрахунку знижок і промокодів. Програма лояльності — нова функція; оскільки бібліотека логіки у версії 1.0 ще не інтегрована у вебінтерфейс, тест-кейси через UI на неї не пишуться, а її функціонал перевіряється ізольовано юніт-тестами Java-модуля.
- **Поза межами (Out of Scope) версії 1.0:** Адміністративна панель (керування замовленнями, товарами, користувачами — запланована на версію 1.1), реальний платіжний шлюз (на demo емулюється), мобільний застосунок.

## 2–4. Рівні та типи тестування

### 2.1. Обґрунтування шкали пріоритетів
- **High:** Критичний функціонал ядра системи (каталог, кошик, чекаут, прямі контракти інтерфейсів API, модульні перевірки логіки лояльності, безпека сесій та цільове навантаження за P-20), без яких функціонування неможливе.
- **Medium:** Допоміжні користувацькі сценарії, розширені конфігурації екранів, надійність сесій, відновлення даних, юзабіліті та перевірка багатопотокових гонок.
- **Low:** Дослідницькі, документаційні, другорядні або обмежені тестовим середовищем задачі (перевірка технічної документації, i18n, l10n за відсутності локалізованого demo та зовнішнє бета-тестування).

## 6. Ризики й припущення

1. **Обмеження публічного демо-сервера:** На публічному ресурсі `practicesoftwaretesting.com` суворо заборонено проводити навантажувальні тести та спроби порушення захищеності. Оскільки локального стенда для «ШопЛайн» немає, таких тестів на demo не виконується.
2. **Періодичне скидання бази demo:** Дані demo-застосунку періодично скидаються, тому тести мають бути незалежними від попередніх замовлень чи створених користувачів.
3. **Модуль лояльності поза UI:** Оскільки бізнес-логіка програми лояльності у версії 1.0 реалізована окремою бібліотекою і ще не підключена до вебінтерфейсу, перевірка правил нарахування та розрахунку проводиться на рівні Unit-тестів.
4. **Наявність дефектів у специфікації SRS 1.0:** Специфікація містить виявлені під час аудиту дефекти вимог (невідповідності порогів доставки, дублювання ID, розбіжності кількості карток); точні тестові очікування формуються на основі виправленої версії SRS 1.1.
