# BPMN-моделі — Спринт 1

Команда: С · Продукт: №1 «ШопЛайн» · Спринт: 1 · Дата: 12.09.2026 · Автор: Горбонос Олександра (ІТ)

Інструмент: **diagrams.net (draw.io)**. Версія нотації: BPMN 2.0 (позначення реалізовані
базовими фігурами draw.io з підписами типу елемента — за потреби легко замінюються на
офіційний трафарет BPMN через панель фігур draw.io: пошук «BPMN»).

Як відкрити файли:
- `.drawio` — https://app.diagrams.net/ (File → Open From → Device)
- Кожен файл містить смуги-пули (Покупець / Магазин.../ зовнішні учасники), події,
  задачі, шлюзи, потоки повідомлень (штрихові лінії), об'єкти даних і анотації.

## Перелік моделей

| Файл | Процес | Типи шлюзів | Таблиця елементів |
|---|---|---|---|
| [01_order-processing.drawio](01_order-processing.drawio) | Оформлення замовлення | XOR (за даними), XOR (за подіями), AND | [element-tables.md](element-tables.md) §1 |
| [02_product-return.drawio](02_product-return.drawio) | Повернення товару | XOR ×3 | [element-tables.md](element-tables.md) §2 |
| [03_contact-request.drawio](03_contact-request.drawio) | Обробка звернення з контактної форми | XOR (за даними), XOR (за подіями), таймер, цикл уточнень | [element-tables.md](element-tables.md) §3 |

Разом у наборі — **3 різних типи шлюзів** (XOR / AND за подіями та даними), норматив
виконано. Таблиця елементів для четвертого процесу («Поповнення складу», OR-шлюз) —
у `element-tables.md` §4, як резерв, якщо команда на Sprint Planning замінить один
з обраних процесів.

Норматив DoD: у кожній моделі — початкова й кінцева подія, доріжки, ≥1 шлюз;
у наборі ≥3 типи шлюзів (✅), ≥1 підпроцес (✅ модель 1, «Комплектація замовлення»),
потоки повідомлень (✅ моделі 1–2), об'єкти даних (✅ моделі 1–2), анотації
(✅ модель 1).

**Наступний крок:** експорт кожної моделі в PDF/PNG (draw.io → File → Export as)
після взаємного рецензування — покладено в `01_....pdf/.png` тощо поряд з вихідником.

Протокол рецензування — у файлі [review.md](review.md).
