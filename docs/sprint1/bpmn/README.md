# BPMN-моделі — Спринт 1

Команда: С · Продукт: №1 «ШопЛайн» · Спринт: 1 · Дата: 22.09.2026 · Автор: Горбонос Олександра (ІТ)

Інструмент: **diagrams.net (draw.io), версія 24.x** (десктоп/веб-клієнт, Help → About
для точної збірки). Версія нотації: BPMN 2.0 (позначення реалізовані базовими
фігурами draw.io з підписами типу елемента — за потреби легко замінюються на
офіційний трафарет BPMN через панель фігур draw.io: пошук «BPMN»).

Як відкрити файли:
- `.drawio` — https://app.diagrams.net/ (File → Open From → Device)
- Кожен файл містить три рівні учасників: пул «Покупець», пул «Магазин» з лініями
  (Сайт/Система, Менеджер, Склад, Бухгалтерія, Адміністратор — за процесом) і
  зовнішні пули-«чорні скриньки» (Платіжний шлюз, Служба доставки). Між пулами —
  лише потоки повідомлень (штрихові лінії); суцільні стрілки не перетинають межу
  пула. Усередині лінія одного пула — події, задачі, шлюзи, об'єкти даних, анотації.

Норматив ≥3 різних типи шлюзів у наборі виконує вже модель 1 сама по собі: XOR за
даними, XOR за подіями, AND. Таблиця елементів для четвертого процесу («Поповнення
складу», OR-шлюз) — у `element-tables.md` §4, як резерв, якщо команда на Sprint
Planning замінить один з обраних процесів.

Норматив DoD: у кожній моделі — початкова й кінцева подія, доріжки, ≥1 шлюз (✅);
у наборі ≥3 типи шлюзів (✅, модель 1), ≥1 підпроцес (✅ модель 1, «Скомплектувати
замовлення»), потоки повідомлень між пулами (✅ усі три моделі), об'єкти даних
(✅ моделі 1–3), анотації (✅ моделі 1 і 3), експорт кожної моделі в PDF поряд
з вихідником (✅ усі три моделі).

Усі пункти DoD для BPMN-моделей закриті.

Протокол рецензування — у файлі [review.md](review.md).
