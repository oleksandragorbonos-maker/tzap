## 1.4. Методологія роботи команди

| Рівень | Що застосовує команда |
|---|---|
| Методологія | Полегшений Scrum: 5 двотижневих спринтів, кожен — Sprint Planning → асинхронні standup → Demo (10 хв) → бліц → Retro (Start/Stop/Continue) → анонімний peer-review; ролі ротуються щоспринта. |
| Методи | User stories за шаблоном «Як…, я хочу…, щоб…» з простежуваністю до очікувань замовника; BPMN 2.0 моделювання бізнес-процесів; рецензування артефактів за чек-листами (не власна робота); трасування вимога → тест-кейс → дефект (з С2). |
| Прийоми | Асинхронний standup замість щоденних зустрічей; ретроспектива Start/Stop/Continue; правило «один виконавець — один рецензент» для кожного артефакту; ведення таблиці задач/Jira з ID артефакту в кожному коміті. |
